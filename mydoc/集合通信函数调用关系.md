---
 AcquireCollectiveCliques 函数负责为 GPU 分布式计算**获取所有必要的集体通信资源**，确保后续 AllReduce、AllGather 等操作能正确执行。

核心流程

**1. 遍历请求的通信组**
函数接收一组 `clique_requests`，每个请求代表一个需要参与的通信组（如某次 AllReduce 涉及的设备集合）。按顺序处理每个请求，提取关键信息：
- [clique_key](file:///home/zzw/code/jax/xla/xla/backends/gpu/collectives/clique_key.h#L58-L58)：通信组的唯一标识（包含哪些设备参与）
- [rank](file:///home/zzw/code/jax/third_party/pygments/pygments/lexers/macaulay2.py#L93-L93)：当前进程在该组中的排名
- [device_groups](file:///home/zzw/code/jax/jax/_src/pjit.py#L306-L306)：设备分组信息

**2. 通过 Rendezvous 机制获取 clique 锁**
对每个 clique，调用 [AcquireGpuClique](file:///home/zzw/code/jax/xla/xla/backends/gpu/collectives/gpu_cliques.h#L72-L77)，核心是 **Rendezvous 同步原语**：

```cpp
Rendezvous<LockableGpuClique::Lock>(
    rendezvous_name, rendezvous_key, num_local_participants, callback, ...)
```

**Rendezvous 的作用**：这是一个屏障同步机制，要求**所有参与者必须全部到达**才能继续。例如 4 卡训练时，如果某个 clique 需要 4 个设备都参与，Rendezvous 会等待最慢的那个设备，防止部分设备提前执行导致死锁。

内部参数：
- [num_local_participants](file:///home/zzw/code/jax/xla/xla/backends/gpu/collectives/gpu_clique_key.h#L86-L86)：需要同步的本地进程数
- [callback](file:///home/zzw/code/jax/jax/_src/callback.py#L0-L0)：仅由**选举出的 Leader** 执行一次

**3. Clique 获取策略（两阶段）**

**阶段一：尝试拆分已有 clique**
检查是否可以从已存在的大 clique 拆分成当前需要的小 clique。例如已获取 `[0,1,2,3]`，现在需要 `[0,1]`，可以直接拆分 NCCL 通信器，避免重复创建开销。

但需满足严格条件：
- 新 clique 必须是已有 clique 的子集
- 所有设备都必须参与拆分（不能部分拆分）

**死锁风险示例**：
```
(1) 设备 [0,1] 执行 AllReduce
(2) 设备 [0,1,2,3] 执行 AllReduce  
(3) 设备 [0,1,2,3] 执行 AllReduce，但分为 [[0,1], [2,3]] 两组
```
步骤 (3) 时，[0,1] 已有独立 clique，但 [2,3] 需要从大 clique 拆分，这会导致死锁。解决方案：**销毁旧 clique，统一从大 clique 拆分**。

**阶段二：创建新 clique**
若无法拆分，则创建新的通信组。此时涉及 **Leader 选举**：

```cpp
CliqueIdCallback default_clique_id_callback =
    [&](const CliqueKey& key) -> absl::StatusOr<CliqueIds> {
      // 仅 Leader 执行
      TF_ASSIGN_OR_RETURN(CliqueId clique_id,
                          params.collectives->CreateUniqueCliqueId());
      return CliqueIds(clique_id);
    };
```

**Leader 选举机制**：Rendezvous 内部保证只有一个进程被选为 Leader，负责生成唯一的 `clique_id`。跨进程场景需外部 KV 存储协调，本地场景直接生成。


**4. 创建设备通信器**
获取所有 clique 锁后，为每个通信组创建实际的设备通信器（如 NCCL communicator）：

```cpp
// 若缺少设备通信器则创建
TF_ASSIGN_OR_RETURN(std::unique_ptr<GpuDeviceCommunicator> dev_comm,
                    comm->CreateDeviceComm(reqs));
```

巧妙的是：**创建通信器本身也是集体操作**，但由于已在 Rendezvous 保护下，可以安全执行。

整个函数本质是**分布式资源的申请与管理器**，通过 Rendezvous 实现可靠的同步，通过 Leader 选举减少冗余操作，通过Leader来为每个设备创建通信器，并返回给调用方。
